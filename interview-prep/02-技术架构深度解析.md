## 一、整体架构设计

### 1.1 系统分层架构

```
┌─────────────────────────────────────────────────────────────┐
│                    VSCode Extension Layer                    │
│  (用户交互、命令注册、Webview UI、状态管理)                    │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                   Agent Reasoning Engine                     │
│  (多轮推理、工具调用、自我反思、上下文管理)                      │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                  Multi-Strategy Search Engine                │
│  (向量搜索、精确匹配、模糊搜索、依赖感知、图搜索)                 │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    Code Analysis Layer                       │
│  (AST解析、URL推导、依赖分析、类型推断)                         │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                      Data Storage Layer                      │
│  (PostgreSQL + pgvector、向量索引、关系数据)                   │
└─────────────────────────────────────────────────────────────┘
```

**设计理念：**
- **分层解耦**：每层职责清晰，便于独立优化和测试
- **双向通信**：Extension ↔ Agent ↔ Search Engine 之间通过事件驱动通信
- **缓存优先**：多级缓存减少重复计算（查询缓存、AST缓存、向量缓存）
- **渐进式增强**：从简单搜索到复杂推理，逐步提升能力

## 二、核心模块详解

### 2.1 索引管理模块 (IndexManager)

**职责：**
- 监听代码文件变化（增删改）
- 触发增量索引更新
- 管理索引队列和优先级
- 协调各子模块工作

**关键设计：**

```typescript
class IndexManager {
  private fileWatcher: FileWatcher;
  private astAnalyzer: ASTAnalyzer;
  private urlDeriver: URLDeriver;
  private embeddingService: EmbeddingService;
  private db: DatabaseService;
  
  // 增量索引：只处理变化的文件
  async indexFile(filePath: string): Promise<void> {
    // 1. 解析AST
    const ast = await this.astAnalyzer.parse(filePath);
    
    // 2. 提取路由定义
    const routes = this.extractRoutes(ast);
    
    // 3. 推导完整URL
    const urlResults = await this.urlDeriver.deriveURLs(routes);
    
    // 4. 生成向量
    const vectors = await this.embeddingService.embed(urlResults);
    
    // 5. 存储到数据库
    await this.db.upsertRoutes(vectors);
  }
  
  // 批量索引优化：合并embedding请求
  async indexBatch(files: string[]): Promise<void> {
    const allRoutes = [];
    for (const file of files) {
      const routes = await this.extractRoutesFromFile(file);
      allRoutes.push(...routes);
    }
    
    // 批量生成向量（减少API调用）
    const vectors = await this.embeddingService.embedBatch(allRoutes);
    await this.db.upsertBatch(vectors);
  }
}
```

**性能优化点：**
- **增量索引**：只处理变化的文件，避免全量重建
- **批量处理**：合并embedding请求，减少API调用次数（从1000次 → 10次）
- **并行解析**：多文件并行AST解析，利用多核CPU
- **智能去重**：相同内容不重复生成向量

### 2.2 URL智能推导模块 (URLDeriver)

**职责：**
- 跨文件追踪变量定义
- 展开模板字符串
- 内联函数调用
- 处理条件表达式

**核心算法：**

```typescript
class URLDeriver {
  private symbolTable: Map<string, SymbolInfo>; // 符号表
  private callGraph: Map<string, string[]>;     // 调用图
  
  // 主入口：推导完整URL
  async deriveURL(node: RouteNode): Promise<string> {
    let url = node.path;
    
    // 1. 展开模板字符串
    url = this.expandTemplateString(url, node.scope);
    
    // 2. 内联函数调用
    url = await this.inlineFunctionCalls(url, node.scope);
    
    // 3. 处理三元表达式
    url = this.resolveTernary(url, node.scope);
    
    // 4. 解析局部变量
    url = this.resolveLocalVariables(url, node.scope);
    
    return url;
  }
  
  // 模板字符串展开
  private expandTemplateString(template: string, scope: Scope): string {
    const regex = /\$\{([^}]+)\}/g;
    return template.replace(regex, (match, expr) => {
      return this.evaluateExpression(expr, scope);
    });
  }
  
  // 函数调用内联
  private async inlineFunctionCalls(url: string, scope: Scope): Promise<string> {
    const callRegex = /(\w+)\(([^)]*)\)/g;
    let result = url;
    
    for (const match of url.matchAll(callRegex)) {
      const [fullMatch, funcName, args] = match;
      const funcDef = this.findFunctionDefinition(funcName, scope);
      
      if (funcDef && this.isSimpleFunction(funcDef)) {
        const inlinedValue = this.inlineFunction(funcDef, args);
        result = result.replace(fullMatch, inlinedValue);
      }
    }
    
    return result;
  }
  
  // 三元表达式处理（状态机解析）
  private resolveTernary(expr: string, scope: Scope): string {
    const ternaryRegex = /(.+?)\s*\?\s*(.+?)\s*:\s*(.+)/;
    const match = expr.match(ternaryRegex);
    
    if (!match) return expr;
    
    const [, condition, trueValue, falseValue] = match;
    const conditionResult = this.evaluateCondition(condition, scope);
    
    return conditionResult ? trueValue.trim() : falseValue.trim();
  }
}
```

**难点突破：**
- **跨文件追踪**：构建全局符号表，支持import/export追踪
- **嵌套展开**：递归处理多层嵌套的模板字符串
- **类型推断**：利用TypeScript类型信息辅助推导
- **边界处理**：处理动态路径参数（如`:id`）

### 2.3 多策略搜索引擎 (SearchEngine)

**职责：**
- 融合5种搜索策略
- 动态调整策略权重
- 结果去重和排序
- 性能监控和优化

**策略融合算法：**

```typescript
class SearchEngine {
  private strategies: SearchStrategy[] = [
    new VectorSearchStrategy(),      // 向量相似度
    new ExactMatchStrategy(),        // 精确匹配
    new FuzzyMatchStrategy(),        // 模糊匹配
    new DependencyAwareStrategy(),   // 依赖感知
    new GraphSearchStrategy()        // 图遍历
  ];
  
  async search(query: string, options: SearchOptions): Promise<SearchResult[]> {
    // 1. 并行执行所有策略
    const strategyResults = await Promise.all(
      this.strategies.map(s => s.search(query, options))
    );
    
    // 2. 结果融合（加权平均）
    const merged = this.mergeResults(strategyResults, {
      vectorWeight: 0.4,
      exactWeight: 0.3,
      fuzzyWeight: 0.15,
      dependencyWeight: 0.1,
      graphWeight: 0.05
    });
    
    // 3. 去重（基于URL + 文件路径）
    const deduped = this.deduplicateResults(merged);
    
    // 4. 重排序（考虑多个因子）
    const ranked = this.rankResults(deduped, {
      relevanceScore: 0.5,
      recencyScore: 0.2,
      popularityScore: 0.2,
      qualityScore: 0.1
    });
    
    return ranked.slice(0, options.limit || 10);
  }
  
  // 结果融合：加权平均
  private mergeResults(
    strategyResults: SearchResult[][],
    weights: Record<string, number>
  ): SearchResult[] {
    const scoreMap = new Map<string, number>();
    
    strategyResults.forEach((results, idx) => {
      const weight = Object.values(weights)[idx];
      results.forEach(result => {
        const key = `${result.url}:${result.filePath}`;
        const currentScore = scoreMap.get(key) || 0;
        scoreMap.set(key, currentScore + result.score * weight);
      });
    });
    
    return Array.from(scoreMap.entries()).map(([key, score]) => ({
      ...this.parseKey(key),
      score
    }));
  }
}
```

**策略详解：**

| 策略 | 适用场景 | 权重 | 优势 | 劣势 |
|------|---------|------|------|------|
| 向量搜索 | 语义相似查询 | 40% | 理解意图，容错性强 | 计算开销大 |
| 精确匹配 | 已知完整路径 | 30% | 速度快，准确率100% | 无容错能力 |
| 模糊匹配 | 部分路径查询 | 15% | 支持通配符，灵活 | 可能返回过多结果 |
| 依赖感知 | 关联API查询 | 10% | 发现隐藏关联 | 需要预构建依赖图 |
| 图搜索 | 调用链查询 | 5% | 深度挖掘关系 | 复杂度高 |

### 2.4 Agent推理引擎 (AgentCore)

**职责：**
- 多轮对话管理
- 工具调用编排
- 自我反思和纠错
- 上下文压缩

**推理流程：**

```typescript
class AgentCore {
  private llm: ClaudeAPI;
  private tools: ToolRegistry;
  private context: ContextManager;
  
  async reason(userQuery: string): Promise<AgentResponse> {
    let round = 0;
    const maxRounds = 5;
    
    while (round < maxRounds) {
      // 1. 构建prompt（包含历史上下文）
      const prompt = this.context.buildPrompt(userQuery, round);
      
      // 2. 调用LLM推理
      const response = await this.llm.complete(prompt, {
        tools: this.tools.getAvailableTools(),
        temperature: 0.3
      });
      
      // 3. 解析工具调用
      if (response.toolCalls && response.toolCalls.length > 0) {
        const toolResults = await this.executeTools(response.toolCalls);
        this.context.addToolResults(toolResults);
        round++;
        continue;
      }
      
      // 4. 自我反思：检查答案质量
      const reflection = await this.reflect(response.content);
      if (reflection.needsImprovement) {
        this.context.addReflection(reflection.feedback);
        round++;
        continue;
      }
      
      // 5. 返回最终答案
      return {
        content: response.content,
        rounds: round + 1,
        toolsUsed: this.context.getToolsUsed()
      };
    }
    
    throw new Error('Max reasoning rounds exceeded');
  }
  
  // 自我反思模块
  private async reflect(answer: string): Promise<ReflectionResult> {
    const reflectionPrompt = `
      请评估以下答案的质量：
      ${answer}
      
      检查点：
      1. 是否完整回答了用户问题？
      2. 是否包含具体的代码位置？
      3. 是否有逻辑错误或矛盾？
      4. 是否需要补充更多信息？
    `;
    
    const reflection = await this.llm.complete(reflectionPrompt);
    return {
      needsImprovement: reflection.includes('需要改进'),
      feedback: reflection
    };
  }
}
```

## 三、数据库设计

### 3.1 核心表结构

```sql
-- 路由表（存储所有API路径）
CREATE TABLE routes (
  id SERIAL PRIMARY KEY,
  url TEXT NOT NULL,                    -- 完整URL路径
  method TEXT NOT NULL,                 -- HTTP方法
  file_path TEXT NOT NULL,              -- 文件路径
  line_number INTEGER,                  -- 行号
  handler_name TEXT,                    -- 处理函数名
  description TEXT,                     -- 描述
  embedding vector(1536),               -- 向量（1536维）
  metadata JSONB,                       -- 元数据
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- HNSW索引（向量搜索）
CREATE INDEX routes_embedding_idx ON routes 
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

-- B-tree索引（精确查询）
CREATE INDEX routes_url_idx ON routes (url);
CREATE INDEX routes_file_path_idx ON routes (file_path);
CREATE INDEX routes_method_idx ON routes (method);

-- GIN索引（全文搜索）
CREATE INDEX routes_description_gin_idx ON routes 
USING gin(to_tsvector('english', description));

-- 依赖关系表
CREATE TABLE dependencies (
  id SERIAL PRIMARY KEY,
  source_route_id INTEGER REFERENCES routes(id) ON DELETE CASCADE,
  target_route_id INTEGER REFERENCES routes(id) ON DELETE CASCADE,
  dependency_type TEXT,  -- 'calls', 'imports', 'extends'
  UNIQUE(source_route_id, target_route_id, dependency_type)
);

-- 搜索日志表（用于优化）
CREATE TABLE search_logs (
  id SERIAL PRIMARY KEY,
  query TEXT NOT NULL,
  strategy TEXT NOT NULL,
  result_count INTEGER,
  latency_ms INTEGER,
  user_clicked_rank INTEGER,  -- 用户点击的结果排名
  created_at TIMESTAMP DEFAULT NOW()
);
```

### 3.2 索引策略

**HNSW索引参数调优：**
- `m = 16`：每个节点的最大连接数（平衡精度和速度）
- `ef_construction = 64`：构建时的搜索深度（越大越精确但越慢）
- `ef_search = 40`：查询时的搜索深度（运行时可调整）

**索引维护策略：**
- **删除优化**：先删除索引 → 删除数据 → 重建索引（10-12x提速）
- **增量更新**：小批量更新直接操作，大批量更新走删除重建流程
- **定期重建**：每周重建一次索引，优化碎片

## 四、技术栈选型理由

### 4.1 为什么选择 PostgreSQL + pgvector？

**对比其他方案：**

| 方案 | 优势 | 劣势 | 为何不选 |
|------|------|------|----------|
| **PostgreSQL + pgvector** | 关系数据 + 向量搜索一体化，ACID保证，成熟生态 | 向量搜索性能略逊专用库 | ✅ **已选择** |
| Pinecone | 向量搜索性能极佳，全托管 | 纯向量库，无关系查询，成本高 | 需要关系查询能力 |
| Milvus | 开源，性能好 | 部署复杂，需要额外维护 | 增加运维负担 |
| Elasticsearch | 全文搜索强大 | 向量搜索支持较弱 | 向量搜索是核心需求 |
| Qdrant | 向量搜索优秀 | 生态不成熟，社区小 | 风险较高 |

**选择理由：**
1. **一体化存储**：关系数据（路由、依赖）+ 向量数据在同一数据库，避免数据同步问题
2. **ACID保证**：事务支持确保数据一致性
3. **成本低**：开源免费，无需额外付费服务
4. **生态成熟**：丰富的工具和库支持

### 4.2 为什么选择 Claude Sonnet 4.6？

**对比其他LLM：**

| 模型 | 上下文长度 | 推理能力 | 工具调用 | 成本 | 为何选择 |
|------|-----------|---------|---------|------|---------|
| **Claude Sonnet 4.6** | 200K | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 中 | ✅ **已选择** |
| GPT-4 Turbo | 128K | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 高 | 成本高，上下文短 |
| GPT-3.5 Turbo | 16K | ⭐⭐⭐ | ⭐⭐⭐ | 低 | 推理能力不足 |
| Llama 3 70B | 8K | ⭐⭐⭐ | ⭐⭐ | 低 | 上下文太短 |

**选择理由：**
1. **超长上下文**：200K tokens支持大量代码上下文
2. **工具调用能力强**：原生支持function calling，准确率高
3. **推理能力优秀**：复杂逻辑推理表现出色
4. **性价比高**：相比GPT-4 Turbo更便宜

### 4.3 为什么选择 Alibaba DashScope Embedding？

**对比其他embedding服务：**

| 服务 | 维度 | 性能 | 成本 | 中文支持 | 为何选择 |
|------|------|------|------|---------|---------|
| **DashScope text-embedding-v4** | 1536 | ⭐⭐⭐⭐⭐ | 低 | ⭐⭐⭐⭐⭐ | ✅ **已选择** |
| OpenAI text-embedding-3-large | 3072 | ⭐⭐⭐⭐⭐ | 高 | ⭐⭐⭐ | 成本高，中文一般 |
| OpenAI text-embedding-3-small | 1536 | ⭐⭐⭐⭐ | 中 | ⭐⭐⭐ | 中文支持不如DashScope |
| Cohere embed-multilingual | 1024 | ⭐⭐⭐⭐ | 中 | ⭐⭐⭐⭐ | 维度较低 |

**选择理由：**
1. **中文优化**：针对中文语义理解优化，适合国内项目
2. **成本低**：比OpenAI便宜约50%
3. **性能优秀**：1536维度，语义表达能力强
4. **稳定性好**：阿里云基础设施，国内访问快

## 五、架构演进历史

### 5.1 v1.0：单策略搜索（2024年1月）

```
用户查询 → 精确匹配 → 返回结果
```

**问题：**
- 只支持精确路径查询
- 无法处理语义相似查询
- 准确率仅60%

### 5.2 v2.0：引入向量搜索（2024年3月）

```
用户查询 → 向量搜索 → 返回结果
```

**改进：**
- 支持语义相似查询
- 准确率提升到75%

**新问题：**
- 向量搜索有时不如精确匹配准确
- 无法利用多种信号

### 5.3 v3.0：多策略融合（2024年5月）

```
用户查询 → [向量搜索, 精确匹配, 模糊匹配] → 结果融合 → 返回
```

**改进：**
- 融合3种策略
- 准确率提升到85%

**新问题：**
- 缺少依赖关系信息
- 无法发现关联API

### 5.4 v4.0：AgentRAG架构（2024年8月 - 当前）

```
用户查询 → Agent推理 → [多策略搜索, 依赖分析, 代码阅读] → 多轮推理 → 返回
```

**改进：**
- 引入Agent多轮推理
- 增加依赖感知和图搜索
- 支持工具调用
