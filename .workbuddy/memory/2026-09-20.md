## 28. 「列出全部 386 个接口」为什么答不出来（排查 + 口径失真）

用户提问背景：仓里显示 386 个接口，但问「列出来」时得到「证据中不包含这 386 个接口的清单数据」。

### 定位（全部落在代码上）

- `/ask` 四个分支**全都**只产出 `evidence = top-K`（`ask.ts:49-54`，limit 10）。
- `llm/qa.ts:251` 明写「如果证据不足，明确指出」⇒ 拒答是**按设计工作**。
- `classifyQuery`（`qa.ts:76-120`）8 类里**没有集合/枚举档**，正则不含「列出/全部/所有/一共」，
  所以「列出所有接口」落到 `general`。

- `url_patterns` 全仓只被读一次：`/repos/:id/stats` 的 **COUNT**（`repos.ts:106`）——
  386 这个数就是从这来的，**没有任何路由返回这些行**；前端 `RepoPage.tsx:639` 只渲染数字。

### 结论

**集合类问题（列全部 N）对检索式问答是结构性无解**：top-K 回答「最相似」，不保证「完备」。
调 K、加 rerank、换嵌入模型都不解决。要完备性只能走 SQL/结构化查询。

### 附带发现（更值钱）：386 是虚高的

- `ALL ${promise}` ← `Promise.all(promise)`；`DELETE ${name}` ← `this._map.delete(name)`。
- 还有 MIME 类型（`text/csv`）、静态路径（`testwire/static/pw/api.json`）混入。
- 根因：`entities.ts:962` `extractHTTPMethod` 用 **子串匹配**（`text.includes('DELETE')`）。
- 粗筛含 HTTP 客户端调用的行：**246 / 386**（约 36% 不像真实接口）。

> **教训**：这个数错很久没人发现，因为 **UI 只显示数字、没有明细**。
> 与「计数 == 0 必须显式失败」是同一枚硬币的两面 —— 只暴露汇总值 = 把错误永久隐藏。
> **正确顺序：先修抽取口径，再谈「完整展示」。**

### 32.3 ✅ 两个独立实现得到一致的真实接口集合（这是本轮最值钱的结论）

两个**互不相干**的实现：

| | 实现 | 展开方式 | 结果 |
|---|---|---|---|
| 离线 | `scripts/interface-inventory.py` | **硬编码** helper 表 | 236 接口（+3 plumbing +1 unresolved） |
| 线上 | `GET /repos/:id/url-patterns` | 从已索引文件**现查** helper 定义 | 238（method 已判定）|

比较前**必须先归一化占位符记法** —— 离线用 `{appId}`、线上归一化用 `:param`。
不归一化会得到「173 条只在线 / 171 条只在离线」的**虚假差异**（纯记法差异，两边其实是同一批路径）。

⇒ 线上实现**没有遗漏任何**离线找出的接口；两个独立实现互相印证 ⇒ 召回完整。
计数差异（236 vs 238）只来自「是否把 4 条 `${url}` 管道线算进接口」。

> **方法论价值 > 本次结论**：判断「清单完不完整」时，不要只信一个实现自报的数字。
> 用**两种不同机制**（硬编码 vs 数据驱动）各自生成一遍，**归一化后做集合差** ——
> 差集为 0 才是真的完整；只看总数相等是会被巧合骗到的。

### 34.2 四个坑（每个都真踩了）

1. **`git checkout <backup> -- <files>` 会把未提交改动静默回退**。工作区有 44 个已暂存改动，
   用备份 ref 取内容 = 丢掉最新工作，而覆盖率检查照样通过。

2. **覆盖率断言空转**：索引被清空后 `keep` 为空，`0 == 0` → 打印「✅ 全覆盖」，
   一条提交没建也报成功。**`not keep` 必须显式失败**（铁律 2 的又一个实例）。
3. **`git ls-files` 把中文路径转义成带引号的 `"01-\351..."`** ⇒ 按前缀分组全部失配，

4. **并行编辑同一文件互相覆盖**：同一轮里对同一文件发两次编辑，后写盖先写，
   而工具报「成功」。`import os` 和 `all_tracked()` 两处就这么丢过一次 ⇒ **同文件多处修改必须串行**。

另有两条纪律：孤儿分支上**绝不能** `git reset --hard`（会不可逆抹掉未提交工作，那些内容任何 commit 里都没有）；
动索引前先存 `git ls-files -s` 快照当验收基准。
